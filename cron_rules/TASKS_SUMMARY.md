## 二、核心执行流程（所有任务统一）

```
cron调度触发（或手动run）
   ↓
wrapper脚本（no_agent模式，stdout即报告）
   ↓
① 数据生成：short_term.py / stock_picker.py
   - 新浪行情API实时数据（MA/RSI/MACD/布林/评分/竞价/支撑压力）
   - 时段自动匹配：9点→早盘 11点→收割后 13点→午后 14点→尾盘
   ↓
② AI解读（模型降级链，脚本内实现）：
   deepseek-v4-flash（超时150s）
      ↓ 失败/过载/超时/空内容
   deepseek-chat（超时240s）
      ↓ 也失败
   ⚠️ 直接输出脚本原始数据（保证用户一定收到内容）
   ↓
③ stdout → cron 原样投递 QQ
```

## 三、分析逻辑（2026-08-05 重构：解决"永远买不到"）

旧逻辑三大缺陷：评分偏抄底但执行要确认、买入区用前期低点（够不着）、涨了禁追跌了说空 → 永远买不到。

新逻辑（已写入3个wrapper脚本prompt + short_term.py点位计算）：

1. **买入区动态化**（short_term.py）：
   - 支撑 = 近5日低点与MA10取较高者
   - 距现价超7% → 自动上移到现价×0.97（回踩2-3%可触发）
   - 操作点位并入当日实时高低点（防止追涨位低于现价）

2. **双买点**：每个品种给 ①回踩买（动态支撑企稳）②追涨买（放量突破近5日高点×1.005）

3. **三段预案写死**：追涨触发X / 回踩买Y / 破位Z放弃（不接）——触发即执行，禁止事后改口

4. **观望必须带触发价**：任何"偏空/观望/等企稳"必须附转多条件（站稳X/突破Y），否则不合格

5. **可执行性强制**：报告末尾必须附【今日可挂单操作汇总】表（挂单价距现价±5%内才允许入表）

6. **套牢盘规则**：半导体设备ETF(159516)、通信ETF(515880) 禁清仓，只做T+加仓（T+1先卖后买）

7. **持仓个股**：北方稀土(600111) 成本39.48，止损37.51，MA10锁定线

8. **时段差异**：
   - 早盘0925：集合竞价铁律（高开≥2%不追/低开<-2%禁买/放量高开=强势），核心=挂单预案
   - 收割后1110：量化收割结束，观察捡漏
   - 午后1330：观察方向确认
   - 尾盘1445：禁止"回踩挂单"废话，必须给"现价直接买/不买"结论
   - 1800个股：收盘后为明日挂单，仅沪深主板（600/601/603/605/000/001/002/003）

## 四、手动执行方式

- 用户要求"手动执行/手动分析"时：
  1. cronjob resume d2543a517b1b（手动实时分析任务）
  2. cronjob run d2543a517b1b
  3. 等待执行完成（约2-4分钟），确认投递
  4. cronjob pause d2543a517b1b（防明天09:00误触发，必须做！）
- 手动任务特性：不套时段模板，通用盘中分析，报告标注数据采集精确时间

## 五、故障兜底

- 模型全挂：输出脚本原始数据（含说明头）
- 脚本超时：short_term 300s / stock_picker 420s 上限

- 手动run间隔：≥30s
